# 方块操作机构：保留问题与后续完善项

本文记录当前第一版 `PickBlockTask`、`PlaceBlockTask`、`BlockArm`、`BlockVacuum` 的已知保留项。

这些项目不是现在必须扩展状态机的内容。第一版先按既定操作流程运行；当实机出现对应现象、需要增加手动控制，或开始提高可靠性时，再回到本文逐项补充。

## 1. 当前第一版的正常使用前提

当前流程默认遵守：

```text
归零完成
→ 自动粗定位
→ 操作手人工微调
→ 操作手确认吸附/释放
→ 自动回到 Safe
→ 再启动下一次 Task
```

在这个流程下，不应在自动运动中途随意中止后继续执行新 Task。

## 2. 尚未补齐的真实动作实现

这些属于后续必做的机构实现，不是当前 Task 框架错误。

| 项目 | 当前状态 | 后续需要补充的位置 |
|---|---|---|
| 双电机归零 | 仅有 `HOMING` 状态 | `BlockArm_Home()` 与 `BlockArm_Process()` 的 `HOMING` 分支 |
| 粗定位目标 | 目标枚举已建立，真实双电机位置尚未填写 | `BlockArm_StartAutoMove()` 的各 `TARGET_*` 分支 |
| 自动到位判断 | `BlockArm_IsReached()` 暂时固定返回 `false` | 比较两个电机反馈、连续到位计数、误差范围 |
| 四方向微调 | 低位取块仅有方向 `switch` 骨架，其他区域尚未实现 | `BlockArm_ApplyFineAdjust()` |
| 微调停止保持 | 已记录当前位置为目标，尚未真正下发保持命令 | `BlockArm_StopAndHold()` |
| 吸附、释放硬件 | 仅有状态切换 | `BlockVacuum_Grab()`、`BlockVacuum_Release()`、`BlockVacuum_Process()` |
| 上层按键与周期调用 | 尚未接入 `main.c` 或控制任务 | 上层遥控输入模块、主循环/RTOS 调度 |

### 2.1 归零参考与限位方案尚未确认

当前 `BlockArm_Home()` 只有 `HOMING` 状态框架，尚未确定机械臂如何可靠建立两个电机共同使用的固定参考系。

需要先向机械组确认或检查装配体、BOM：

```text
是否安装微动开关、霍尔开关或光电开关等限位传感器？
两个主动自由度是否各自有可重复的机械参考位置？
两个参考位置共同成立时，是否唯一对应安全收位姿态？
```

推荐的最终方案：

```text
机械挡块：限制机构的真实极限位置
限位传感器：向软件报告已抵达参考位置
BlockArm_Home()：按机械验证的方向和顺序，让两个电机低速寻找参考位置
→ 分别记录 motor_a_zero_position / motor_b_zero_position
→ 保持收位姿态
→ BlockArm = READY
```

若暂时没有限位传感器，第一版可以采用临时的“堵转式归零”：

```text
电机低速朝机械挡块运动
→ 一段时间内反馈位置变化很小
→ 暂定已经抵达挡块
→ 记录当前位置为软件零点
```

这只是折中判据，不等同于限位开关。位置不变还可能来自力矩不足、连杆卡滞、通信异常或电机失能；因此必须限制归零速度、设置归零超时，且不能长时间持续顶住挡块。

归零时的分层职责保持为：

```text
BlockArm：决定 A/B 电机的回零顺序、读取限位或堵转判据、记录两个零点、判断 Home 是否完成
Motor：提供 Motor_SetSpeed()、Motor_SetPosition()、Motor_GetPosition() 等通用电机接口
DJI / ZDrive Driver：执行各自的实际通讯和控制
```

## 3. 保留的状态边界问题

### 3.1 `STOPPED` 状态允许启动新 Task

当前 `PickBlockTask_ArmCanStart()` 和 `PlaceBlockTask_ArmCanStart()` 都允许机械臂在：

```text
READY
REACHED
STOPPED
```

时启动新 Task。

`STOPPED` 既可能表示“人工微调后正常停下”，也可能表示“自动运动中途被外部 Stop 打断”。后者的机构姿态可能是中间姿态，因此理论上不适合直接启动新的取块或放块任务。

第一版处理方式：

```text
自动动作中途 Stop 后，不继续正常 Task；
人工处理、重新归零，或重新回到已知 Safe 姿态。
```

以后如需要更严格保护，可让新 Task 仅允许从 `READY` 或 `REACHED` 启动，并增加“当前位置/已到达目标”的记录。

### 3.2 自动动作中途 Stop 后仍保留微调区域

自动前往低位取块时，内部会保存：

```text
fine_adjust_active = false
fine_adjust_profile = LOW_PICK
```

这里两个变量含义不同：

```text
fine_adjust_active：当前是否正在人工微调
fine_adjust_profile：以后微调时应采用哪组区域参数
```

如果自动动作在中途被 `BlockArm_Stop()` 打断，当前代码会变为：

```text
state = STOPPED
fine_adjust_profile = LOW_PICK
```

因此理论上仍可调用 `BlockArm_StartFineAdjust()`，即使机构还没有到达真正的低位取块粗定位区。

第一版处理方式：

```text
自动动作中途 Stop 后，不继续人工微调。
```

以后如需程序自动阻止，可在“自动运动被 Stop”的分支中将：

```c
block_arm.fine_adjust_profile = BLOCK_ARM_FINE_PROFILE_NONE;
```

而人工微调松开时不清除该值，以便允许继续细调。

### 3.3 未记录“当前已到达的业务位置”

现在 `BlockArm` 能报告：

```text
REACHED
```

但不能明确报告：

```text
到达的是 Safe、低位取块、第一层放块，还是其他位置。
```

第一版按固定操作流程使用即可。

以后若要限制“只有在 Safe 才能开始下一次 Task”，可增加一个内部变量记录最近一次自动到位目标，例如：

```c
BlockArmTarget_t reached_target;
```

## 4. 可靠性与故障处理保留项

### 4.1 自动动作、吸附、释放超时

当前以下计数变量已经保留：

```text
motion_count
grab_count
release_count
```

但还没有用于超时判断。

未来应分别处理：

```text
自动运动超时 → BlockArm = FAULT
吸附超时     → BlockVacuum = FAULT
释放超时     → BlockVacuum = FAULT
```

人工微调不建议采用短超时，因为操作手需要自行观察和决定对准时间。

### 4.2 `FAULT` 后的恢复路径

当前设计不做自动故障恢复。Mechanism 进入 `FAULT` 后，Task 会进入自己的 `FAULT` 状态。

第一版可采用人工处理：

```text
停止机构
→ 检查机械、电机和真空气路
→ 重新初始化/重新归零
→ 再开始 Task
```

以后如需要更方便的恢复，可增加明确的 Fault Reset 接口，但不建议现在做自动重试。

### 4.3 微调方向非法值保护

当前 `BlockArm_StartFineAdjust()` 对正常遥控按键调用足够使用。

以后若上层输入来源增多，可增强为：

```c
if (direction < BLOCK_ARM_FINE_FORWARD ||
    direction > BLOCK_ARM_FINE_DOWN)
{
    return;
}
```

并在内部方向 `switch` 中补充 `default` 分支。

## 5. 放块释放时的稳定性

当前 `PlaceBlockTask_ConfirmRelease()` 执行：

```text
停止微调
→ 立刻开始释放真空
```

第一版操作规范：

```text
先松开微调方向键
→ 观察方块已由下方可靠支撑且姿态稳定
→ 再按确认释放键
```

若实机出现“释放时方块仍在晃动、偏移或倾倒”，再考虑增加一个短暂的稳定等待状态；当前不增加该状态。

## 6. Safe 姿态的位置保持

Safe 不是独立电机模式，而是两个电机的一组位置目标。

正确逻辑是：

```text
BlockArm_MoveToSafe()
→ 两个电机进入 Position 模式并接收 Safe 目标
→ BlockArm 判断到位并进入 REACHED
→ 目标位置保持不变
→ Motor/Driver 周期控制持续维持 Safe 姿态
```

注意：到达 `REACHED` 后不能调用 `Motor_Disable()`，否则机械臂可能因重力下落。

## 7. 出现现象时的排查入口

| 实机现象 | 优先查看 |
|---|---|
| 自动运动一直不结束 | 到位判断、反馈更新、`motion_count` 超时 |
| 自动运动中途停止后还能误微调 | 第 3.2 节 |
| 在未知姿态启动了新 Task | 第 3.1、3.3 节 |
| 吸盘一直吸不上或流程卡在 GRAB | 真空反馈、`grab_count` 超时 |
| 吸盘释放后流程卡住 | 真空释放判据、`release_count` 超时 |
| Safe 到位后机械臂下落 | Motor 位置模式、底层周期函数、是否误调用 `Motor_Disable()` |
| 放块后方块偏移或倾倒 | 操作手确认时机、释放稳定性、放块微调参数 |

## 8. 当前结论

当前 Task 主流程和 Mechanism 分层可以继续作为第一版基础。

本文中的保留项不要求现在全部实现。优先顺序建议为：

```text
归零
→ 粗定位目标与位置模式
→ 到位判断
→ 真空硬件与确认
→ 微调参数
→ 超时与状态边界加固
```
